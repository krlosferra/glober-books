## Numbered rulings and follow-ups

1. **O-1, SC-27 HTTP-client ban. Ruling: add it now, through a one-line amendment of Task 02. Conditional on PM and Security agreeing.**
   - Reason: `security.md` SC-27 verification reads "Dependency tree and grep for HTTP clients; no `RestTemplate`, `RestClient`, `WebClient`, `HttpClient`, `URL.openConnection`", and Task 02 traces SC-27. The task text lists only four bans, so the trace is not met without the fifth.
   - Deferral has no natural owner. The "task that first needs it" has no reason to add a ban, so it would be forgotten (Module 2, context drift: intent that lives only in a handoff).
   - The cost is one `RegexpSinglelineJava` module plus one seeded run. Task 02 is not DONE, so amending it is not a reopening.
   - Required steps: (a) the PM amends Task 02 acceptance criterion 1 to add "and an SC-27 ban on outbound HTTP clients in `src/main`"; (b) Java adds the module and the evidence in a fixup commit on the same branch; (c) Security confirms the pattern.
   - Pattern review. The proposed `\b(RestTemplate|RestClient|WebClient|HttpClient|HttpURLConnection)\b|\.openConnection\(` is acceptable. Two things need to be recorded: it runs under `RegexpSinglelineJava` with `ignoreComments`, and it is suppressed for `src/test` by adding `SC-27` to the existing message-prefix suppression. Imports of those types match by type name, which is wanted. It does not cover `java.net.Socket`, `URL.openStream` or `HttpClient.newBuilder` without the type name. State that this is a type-name tripwire and not a proof of no egress. The dependency tree plus the SC-27 runtime evidence are the other layers.
   - Alternative if the PM refuses: defer, and write into `tasks.md` the task that owns SC-27 (the first controller task) by ID. Not preferred.
2. **O-2, wall-clock ban in tests. Ruling: keep tests exempt for now.** The time rule exists so business time is injectable. Fixtures in tests are legitimate (SC-07, SC-14 and SC-27 scope is `src/main`). A test calling `Instant.now()` is a flakiness risk, not a security risk. Revisit in Task 03a, when the injected `Clock` exists: the PM may then decide to scope a test-side `TIME-RULE` without the exemption. Record it as a note to the Task 03a brief. No change now.
