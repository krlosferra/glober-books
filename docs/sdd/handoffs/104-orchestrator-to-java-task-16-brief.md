## Binding constraints
1. Stage order stays: Host, Origin, Fetch-Metadata, Content-Type, body cap, route and method, Accept, then id, query, empty body. Never read parameters through the servlet parameter API (`getParameter*`); parse the raw query string.
2. Id rule (criterion 1): the check is a pure function judged on the raw path segment as received (lower-case 36-character UUID; any `%`, upper case or wrong length gives `400 MALFORMED_REQUEST`), invoked by the gate after route and method are known. No id route exists until Task 31, so test the id rule at unit level and through the gate with a test-only route table fed to the filter (the route table is a constructor argument, not a property); the real-port rows E-24 row 1, E-27 rows 1 and 2 and T-14 are completed by Task 31. Say so in the delivery.
3. Query rule (criterion 2): on the list endpoint only `status` is allowed; a non-empty query on any other endpoint (static content included), an unknown or repeated parameter, an empty pair, malformed percent-encoding, invalid UTF-8, or 2,000 or more pairs gives `400 MALFORMED_REQUEST`; `?` alone and `?status=%72eading` pass; a `status` value other than exactly `unread`, `reading`, `completed` (including `READING`, empty, `?status`, `reading+`) gives `400 INVALID_STATUS` after the shape check. Pass the decoded value to the controller as a request attribute (the list endpoint of Task 07 does not filter yet: do not add filtering, that is Task 23b).
4. No-body rule (criterion 3): any body byte on GET or DELETE gives `400 MALFORMED_REQUEST` (read at most one byte; no `Content-Length`, `Content-Length: 0` and a zero-length chunked body pass); a chunked body over 16,384 bytes gives `413` on any route.
5. Early rejection (criterion 4): `Expect: 100-continue` with an oversized declared length gets `413` and no `100 Continue` (the connector already answers 100 only on read: keep it); a request rejected with 415 that declares 10 MiB answers within 2 s while another request is served.
6. Slow requests (criterion 5): a connection with no complete request within 5 s is closed while others are served (live test with a raw socket, no `Thread.sleep` as synchronisation: blocking reads with timeouts). Run the drip variant (one byte every 2 s on the request line, on the headers and on the body of a valid POST), record the real result; if a connection survives past a reasonable total, add a total read deadline in `BoundedBodyRequest` or report the limit to the Sponsor as an accepted limit, and say which in the delivery (SEC-F-073). Do not change SC-06 values (Tomcat limits): ASK FIRST.
7. Reuse `MalformedRequestException` and the existing error factory and writer; no new error codes; no new dependency; no change under `backend/config/**` or `pom.xml`. Carry-over (optional, cheap): tighten `HeaderPolicyTest` to an exact equality of the full `Permissions-Policy` value (Task H1 follow-up).
