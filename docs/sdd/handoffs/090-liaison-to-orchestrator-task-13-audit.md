## Rulings
1. (a) Busy-port check at config load: ACCEPT. It is outside the brief's wording but inside its intent (AC1: a busy port fails the run), and it was forced by a measured Playwright behaviour (readiness probe waits before the command starts). It reuses the launcher, hardcodes the port, reads nothing from the environment, and only the runner process runs it. Caveats: it also fires on `--list`; there is a small race between this check and the launcher check, which is covered because the launcher re-checks. Follow-up F1: comment in config that the two checks are deliberate, and that `--list` fails on a busy port.
2. (b) `grepInvert` skipped on `process.argv.includes('@isolation')`: ACCEPT WITH FOLLOW-UP. It works for the documented form `--grep @isolation`, but it is fragile: `--grep=@isolation` or `-g @isolation` as one token will not match and the test stays excluded (fails safe, test not found). It also matches any argument containing exactly that token, such as a file name. Follow-up F2: Task 14 README must give the exact command `npx playwright test --grep @isolation`; consider a dedicated `isolation` project instead if the hack causes trouble. Not a security issue (the exclusion fails safe).
3. (c) `__dirname`: ACCEPT. Without `"type": "module"` Playwright transpiles to CommonJS; editing package.json was out of scope. Note that the launcher is `.mjs` and uses `import.meta` correctly. Follow-up F3: if Task 14 or later adds `"type": "module"`, `__dirname` in config and global-setup breaks; record this in a comment in the config.
