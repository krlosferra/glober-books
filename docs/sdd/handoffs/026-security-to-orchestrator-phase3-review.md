## 4. Review of the items requested in handoff 024

1. **Pipeline order (AP-2).** Correct for the stated threats: headers, Host, Origin and Fetch-Metadata decide before the Content-Type, which decides before any body byte is read; the declared length is checked before reading and `Expect` gets no `100`; route, id and query are judged from the raw target, which is the only way to see `%2e%2e` and `//`; strict JSON follows. Gaps are only those of SEC-F-066 (container answers), SEC-F-073 (deadline) and the rule that the gate registers for the request dispatch only while `sendError` is wrapped (Task 17 test must show an error dispatch cannot bypass the headers).
2. **Start order and validation without WAL.** The order (guard, header test with plain I/O before SQLite touches the file, claim, read-only validation, then writes) is sound and the WAL refusal by bytes 18 and 19 is a good fail-closed step. Conditions: SEC-F-068 (validator), SEC-F-069 (claim), SEC-F-074 (hot journal and the size test).
3. **Exclusive-lock claim.** Plausible, unproven; see SEC-F-069. N-2 and N-3 stay "proved by test" items; the fallback (no-op write transaction) is acceptable.
4. **`query_only` validation.** Adequate as a second guard (it does not stop journal recovery, see SEC-F-074; `trusted_schema` OFF applies while the untrusted schema is parsed). The order inside the validator is SEC-F-068.
5. **Tomcat limits.** The numbers equal SC-06. Additions: explicit `max-swallow-size` and the deadline question (SEC-F-073); wording and capacity interplay (SEC-F-078).
6. **Wrapper placement (N-4).** Accepted on the conditions of SEC-F-066.
7. **Static catalog rules.** Sound (fixed set, extension allowlist, exact paths, no validators, no ranges, no conditional answers, Maven exclusions). Condition SEC-F-072.
8. **Tier moves, D1 to D4, M.** Confirmed, section 5.
9. **CR-1 to CR-9 for security effect.** CR-1, CR-2, CR-3, CR-5, CR-6: none (text only, rendered with `textContent`, no new input). CR-4: SEC-F-075 (accept). CR-7: ignoring entries whose `field` is not `title`, `author` or `status` is the safe choice; server message text is still shown only through `textContent`. CR-8: SEC-F-079 (accept). CR-9: SEC-F-074 (accept with Task 34 cases); it does not let the application itself change an invalid file, only SQLite's own recovery can, and only for a journal planted by someone with write access to the data directory.
10. **Frontend E2E isolation.** SEC-F-070. The rest of AP-9.2 holds: literal `127.0.0.1:18080`, `reuseExistingServer: false`, a busy port fails, one worker, the database never opened by test code, deletion only of the launcher's own directory.
11. **Accessibility checker.** SEC-F-076; the decision of the Sponsor (test code only, CSP never relaxed) is consistent with SC-10 and SC-38.
