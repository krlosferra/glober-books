## Binding constraints
1. Creation (criterion 1): on an empty temporary location the guard creates the missing directory with mode 0700 and the missing database file with mode 0600 BEFORE any connection is opened, independent of the process umask (test with umask 022 and with 000, set through the creation call with explicit POSIX permissions and an explicit permission set after creation if needed; do not rely on `umask` of the test JVM). Any companion file path the guard prepares is also no wider than 0600.
2. Refusal (criterion 2): a symbolic link as the directory or the file (also a link in the guarded path, and a dangling link), another owner, any group or other permission bit on the directory or file: the guard refuses with a fixed reason; the file is untouched (compare SHA-256 and modes before and after; nothing is created, chmod-ed or deleted by the refusal). The sandbox runs as root, so a mode check by trying to read is meaningless: read the attributes (owner uid, POSIX permissions, `NOFOLLOW_LINKS`) explicitly. To test "another owner" use `chown` to a different uid through `Files.setOwner`/`PosixFileAttributeView` when running as root; if the environment cannot, say so and state the limit; do not skip silently. On non-POSIX file systems the check is not made (documented platform limit, US-009.6).
3. Uncreatable or untrustworthy location (criterion 3): a path that is not absolute after resolution, a symbolic link in the guarded path, a parent that is missing or not a directory, the "unable to open database file" case of SEC-F-098 and SEC-F-140: the guard refuses with a fixed reason holding no path of a book and no book data; no file or directory is created outside the guarded directory (assert by listing the parent before and after).
4. Reasons (criterion 4): every refusal reason is a fixed string (an enum or constants), never built from a path, an owner name, a mode string or any cell value; assert this in a test (the reason for two different bad locations is the same fixed string per category). No logging of paths of books.
5. Identity (criterion 5): the file identity remembered by the guard (device and inode through `fileKey` or the platform equivalent, and the file's regular-file status) is compared with the identity after the pool opens; prove it with a unit test with two distinct files (same identity accepted; a swapped file refused). The race between check and open is not testable without a test-only switch (A-09): write it down as a documented limit in the delivery and the Javadoc, for the Sponsor to agree (handoff 027). No test-only switch or property in `src/main`.
6. Keep the existing provider behaviour and tests green (claim, pragmas, journal mode, `SqliteStoreIntegrationTest`, `ClaimChildMain`). All files at or under 300 lines. Expected values come from the spec and the security notes, not from the code. No `Thread.sleep`.
