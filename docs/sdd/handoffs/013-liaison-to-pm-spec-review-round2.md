## 4. Rulings requested (handoff 012 section 6)

1. **Statuses 414, 501, 505 (and 400, 431, 405) for pre-application answers.** No constitution amendment is required for the Phase 2 gate. Reasoning: the constitution does not name 400 or 431 under R-13 (see Summary); its Error Handling text says only that protocol-level errors answered by the container before application code runs are a signed residual risk with a generic body that may lack the security headers, and its "Status codes" line lists the statuses of responses the application produces. The spec confines 414, 431, 501 and 505 to those container answers, never produced by the application, so there is no conflict. Do not word it as "the only statuses outside Appendix A" in a way that suggests the spec widens the constitution's list (N-08 fixes that). A clarifying sentence in the constitution is recommended hygiene so the next reader does not reopen the question; it is the Sponsor's to apply, non-blocking, and may travel with the next constitution revision. Exact text (add to the end of the "Status codes:" line in Error Handling Standards): "Answers that the container gives before application code runs (R-13: invalid request line, over-long line or header, framing conflicts, unsupported method token or protocol version) may additionally use 400, 405, 414, 431, 501 or 505, with a generic body and no product or version; the application itself uses only the statuses above."
2. **Quoted `charset`: confirm 415.** HTTP allows the quoted form, so this is a deliberate narrowing; the narrowing is recorded in DEC-027, costs no real client (the page sends the unquoted form), and removes a parser path. Condition: the narrowing stays named in DEC-027 as it is now.
3. **`Accept` with `q=0`: confirm exclusion.** It is the defined meaning of `q=0` in HTTP; my round-1 "ignore q" was the simpler reading but yields `200` for a client that said it does not accept JSON. Condition: add the `q` syntax of P-6 so every row has one answer.
4. **Query or body on the static page: confirm `400 MALFORMED_REQUEST`.** One rule for the whole application is better than a special case, and the page is opened by typing, a bookmark or the console. Condition: record the consequence (a link with tracking parameters gets a JSON error) in Section 6, which is N-11 (a) and S-3.
