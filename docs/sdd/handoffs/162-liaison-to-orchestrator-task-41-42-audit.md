## Key judgments
- **(3) Latency of C-11 (c).** The spec does not bound it: C-11 (c) lists status, counts, no 500, no refused connection, nothing failed changed, process serves. The 2 s of M-2 covers only (a) and (b). So 7.05 s is within the spec and recording it is enough for acceptance. The real SEC-F-167 question (does any request wait more than 5 s for the one pooled connection) is answered by the outcome, not by the figure: a pool timeout would be a 500 and the test asserts 201 for all 50 adds. What the figure does not show is the margin: it measures the client exchange, not the pool wait, and a slower machine could cross 5 s for the last queued add (F-2).
- **(4) Slow readers not cut.** Inside the criterion (no OOM, serves afterwards; the criterion does not ask the server to cut). It is a real finding for the Sponsor, already in the ledger as S-6: with 8 slow readers all 8 Tomcat threads are held for the length of the read (here at least 12 s; the first trial with 40 s was the same) and the application serves nobody else meanwhile, an availability limit on loopback. A response-write timeout is a production and SC-06 change: ASK FIRST, not done. R-24 (drip clients) is the accepted sibling for the request side; this is the response side and is not yet in section 4 "Accepted limits".
- **(4) 512 MB.** Confirmed by measurement: peak heap about 230 MB (about 45%), no case for another value. README text: see F-1.
- **(5) SEC-F-166.** Cold on a fresh JVM, 4,999 maximum-size books with one shared 200-code-point author (the worst case of the duplicate scan): first add 392 ms; first request being the duplicate of book 0, 2499, 4998: 444, 428, 488 ms; all under 2 s, assertion `< 2 s` in the test, 4x margin, against the earlier probe of 1.64 s on a cold JVM (security-log SEC-F-166). Caveat confirmed by me in the test class: the harness readiness check is a list request, so the list path is warm and the add and duplicate paths are cold. The second test starts one JVM per book so each duplicate is a true first mutating request. Same machine only (4 CPUs, Java 21.0.12.1); the Sponsor's machine is the reference environment of M-2, so the figure is evidence, not a guarantee.
- **(7) Test quality.** Oracles are the spec's. Gaps: F-3 (slow readers' status not asserted), F-2. Times: 3.9 s, 30.7 s, 22.2 s, all under 60 s; the full verify (7 min 42 s) is above the 6-minute figure in the plan (the PM already has that as a plan amendment, section 6 of the ledger).
