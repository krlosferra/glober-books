**F-13 CR-5 leaves the oracle for US-013.4 ambiguous.** The definition says a failure causes "exactly one replacement ... not a clearing followed by a filling". AP-8 says the area "is cleared at the start of the next user action". A `MutationObserver` that watches from click to failure sees two writes (clear, then fill); one that watches from response to fill sees one. Task 44 AC4 would pass or fail depending on the window. Required: CR-5 states the window ("from the arrival of the failure to the end of its handling") or AP-8 drops the separate clear (each message replaces the previous one). Proposed spec text: "an update is one replacement of the text of the live region; the clearing of the region when the user starts a new action is not part of any failure's update, and a failure causes exactly one replacement between the arrival of its outcome and the end of its handling." Task 44 AC4 then names that window.

**F-14 CR-9 does not say what happens to a hot journal beside a file that is not valid.** The exception is "a file that was valid before that termination". The application cannot know that at start; SQLite rolls back any hot journal it finds at the claim (plan N-1). If a journal is present next to a damaged or foreign-structure database, either the bytes change (violating the sentence that precedes the exception) or the plan must refuse before the claim. Tests need an oracle for: (a) valid database plus journal from a killed instance (Task 34 AC3, fine); (b) invalid database plus a genuine hot journal; (c) a planted or garbage `-journal` next to a valid or invalid database. Required: spec text that states the outcome for (b) and (c), and a Task 34 AC for each. Proposed CR-9 closing clause: "...which restores the last committed state; a journal file that is not a valid journal of that file is ignored by the storage and changes nothing, and in every case the outcome of the validation (accept or exit non-zero) is judged on the file after that rollback." This is the intended reading asked in handoff 023 (c): the reading is right for case (a) and incomplete for (b) and (c). Security should judge planted-journal risk.
